# 02 · CQ 环：让 CAM_A 自己跑起来

## 1. 环长什么样

一条命令 8 字节：

    word0 = (cmd << 16) | reg_offset
    word1 = 数据（指向「数据影子」里 reg_offset 位置的 IOVA，或立即数）

cmd 的含义：

| cmd | 含义 |
| --- | --- |
| 0x1800 | 写寄存器 |
| 0x1801 / 0x1802 / 0x1803(0x180C/0x180D/0x180E/0x1833 等) | 写寄存器（不同总线/字段宽度，行为等价于写） |
| **0x1805** | **写寄存器 + 触发 DB 装载**（关键） |
| 0x1807 / 0x1808 / 0x1812 / 0x1865 | 写寄存器 |
| 0x19FD / 0x18FB | 表命令（原厂 HAL 元数据，重放时跳过） |

数据影子（shadow）就是一块按「寄存器偏移」索引的 u32 数组：环条目 word1 指向 shadow_base + reg_offset，
所以我们只要改影子里的某个 u32，就改了这一帧的配置（不用改环本身）。

**历史卡点解释**：静态直写 P1 寄存器 + 一次 DB_EN 边沿，只能写出 3968 B（25 行）就永久背压。
原因就是 P1 的配置必须**每帧用 0x1805 重装一次**，Android 的环里 0x1805 出现 4 次。

## 3. 怎么让 CQ 跑起来

    ; 1) 静态组（每帧不变）
    CAM_A + 0x4820 = IMGO iova      ; 主输出（另见 0x4878，双写同值）
    CAM_A + 0x484C = FH iova
    CAM_A + 0x4808 = meta iova
    CAM_A + 0x47B0 = meta iova
    CAM_A + 0x0E00 = 0              ; 关 FBC
    CAM_A + 0x0E08 = 0
    CAM_A + 0x014  = 1
    ; 2) 环配置
    CAM_A + 0x0200 = 0x112          ; CQ 模式
    CAM_A + 0x0214 = ring_iova      ; 当前环
    CAM_A + 0x0218 = 0xD98          ; 环长（435 条时；41 条时按实际字节数写）
    CAM_A + 0x0210 = 0x11           ; immediate：CPU kick 才跑一次
    ;   或  0x00000021              ; 连续：TG 的 VSYNC 每帧自动重放（后摄可用，前置会自复位）
    ; 3) DB_EN 0->1 边沿，然后 kick
    CAM_A + 0x0054 = 0
    CAM_A + 0x0054 = 0x120074
    CAM_A + 0x0074 = 1

判据：等 40 ms 后读 0x1F78 应为 0x0079EC00（一帧像素数），0x1F3C byte1 = 0x04 表示 CAM 已接管出流。

## 4. 环里有条「下一环地址」

金标环里有一条写 0x214（下一环地址 = 原厂 HAL 的环缓冲）。**不改回自己的环，CQ 就只真跑首帧**
（症状：IMGO base 被锁存、帧不再更新）。
采集器的解法（零 CPU 干预的硬件轮转）：

1. 分配 8 份环副本、8 份影子副本、8 个 next-ring cell（每个 cell 一个 u32，放下一份环的 IOVA）。
2. 环 i 里那条 0x214 命令的 word1 指向 cell_i（而不是立即数）。
3. CQ 执行到它时把 cell_i 的值装进 0x214 —— 于是自动切到环 i+1。
4. 软件每帧只往前推一格，改 cell 内容即可（实际是初始化时一次性写好环形关系）。

布局（camrec6 的 AUX 区，单块 ≤32 MB 受 camreg 限制）：

    RING_OFF   = 0x00000   步长 0x1000   环 ×8
    DATA_OFF   = 0x10000   步长 0x8000   影子 ×8（约 4 KB 有效 + 余量）
    CELL_OFF   = 0x50000                  next-ring cell ×8
    FH_OFF     = 0x51000
    META_OFF   = 0x52000
    AAO_OFF    = 0x53000   0x60000        AAO 硬件统计（3840 B × 90 行）

## 5. 尺寸与内存

* 一帧 RAW10 = 2448 行 × 4080 B = 9,987,840 B（宽 3264 × 10 bit 打包成 4080 B，行尾无填充）。
* 采集器 8 槽，槽步长 10 MB（0x00A00000），3 槽一组共 30 MB。
* IMGO base 必须是 **camreg ALLOC 返回的 IOVA**（0x68000000 起的 IOMMU 窗）。写物理地址会让 P1 崩。

## 6. 前置摄像头的差别

GC05A2 走同一个引擎，但：

* 端口是 CSI 端口 2（ANA 0x11C88000、DPHY 0x11C8A000），seninf5（0x1A008000），2-lane。
* 环 439 条、与后摄只差 4 条；尺寸 2592×1944，一帧 6,298,560 B，行 stride 3248、有效 3240、行尾 8 B 填充。
* **连续模式（0x210=0x21）会自复位**，只能 0x11 + 每帧 CPU kick。
* Android 侧抓下来的「数据影子」里 0x1000+ 区域其实是 CQ 环缓冲区内容（污染），
  必须用 live 全窗寄存器重建 DATA 区（0x1A030000..0x4FFF，5120 条）后才有满帧。
